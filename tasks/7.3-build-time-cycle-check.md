# Task 7.3 — Optional build-time cycle check

## Goal
When the user enables `FailBuildsOnCycles` in Project Settings (Task 5.5), Unity
builds must abort early with a clear error if any dependency cycle exists between
**project** asmdefs.

## Files to create
- `Editor/Build/CycleBuildPreprocessor.cs`

## Specification

### Class
```csharp
internal sealed class CycleBuildPreprocessor : IPreprocessBuildWithReport {
    public int callbackOrder => 0;
    public void OnPreprocessBuild(BuildReport report);
}
```

### Behavior
1. Early-out when `AssemblyArchitectSettings.instance.FailBuildsOnCycles` is `false`.
2. Build a `DependencyGraphModel` from `new AsmDefRepository().LoadAll()`.
3. Filter to nodes whose `Origin == AsmDefOrigin.ProjectAssets` (cycles in package
   code are out of the user's control).
4. Run `CycleDetector.FindCycles(filteredModel)`.
5. If any cycles, throw `BuildFailedException` whose message lists each cycle on its
   own line, e.g.:
   ```
   Assembly Architect: 2 dependency cycle(s) detected. Builds aborted.

     Cycle 1: Acme.Foo → Acme.Bar → Acme.Foo
     Cycle 2: Acme.UI → Acme.Core → Acme.UI

   Disable "Fail builds on cycles" in Project Settings ▸ Assembly Architect to
   build anyway.
   ```

### Filtering helper
Add a small helper to `DependencyGraphModel`:
```csharp
public DependencyGraphModel Filter(Func<AsmDefNodeModel, bool> predicate);
```
which returns a new model with non-matching nodes (and their edges) removed. Cover
with a test in Task 6.1's spirit (add to the existing test file).

## Acceptance criteria
- Setting enabled + cycle present ⇒ build fails with the formatted message above;
  Console shows the message at error level.
- Setting enabled + no cycles ⇒ build proceeds normally.
- Setting disabled ⇒ build always proceeds, regardless of cycles.
- Console clean during normal Editor usage (preprocessor only triggers on builds).

## Out of scope
- Multi-target build complexity beyond what `IPreprocessBuildWithReport` provides.
