# Task 2.2 — Build the toolbar

## Goal
Populate the toolbar slot from Task 2.1 with all controls the rest of the package will
need. Each control should expose an event but contain only stubbed behavior; later
tasks subscribe to those events.

## Files to create / edit
- `Editor/Window/Toolbar/AssemblyArchitectToolbar.cs`
- `Editor/UI/AssemblyArchitectToolbar.uxml`
- `Editor/UI/AssemblyArchitectToolbar.uss`
- `Editor/Window/AssemblyArchitectWindow.cs` (instantiate the toolbar in `CreateGUI`)

## Controls (left → right)

| Control                    | Type                | Event property                  |
|----------------------------|---------------------|---------------------------------|
| Refresh                    | `ToolbarButton`     | `Action RefreshRequested`       |
| Layout dropdown            | `ToolbarMenu`       | `Action<LayoutKind> LayoutRequested` |
| Save Layout                | `ToolbarButton`     | `Action SaveLayoutRequested`    |
| (flexible spacer)          |                     |                                 |
| Search field               | `ToolbarSearchField`| `Action<string> SearchChanged`  |
| Show Packages              | `ToolbarToggle`     | `Action<bool> ShowPackagesChanged` |
| Show Built-ins             | `ToolbarToggle`     | `Action<bool> ShowBuiltInsChanged` |
| Mini-map                   | `ToolbarToggle`     | `Action<bool> MiniMapToggled`   |
| Overflow menu (`⋯`)        | `ToolbarMenu`       | items: "Open Project Settings", "Open Documentation", "Reset Layout" each with their own event |

`LayoutKind` is an enum: `Hierarchical`, `ForceDirected`. Defined in
`Editor/Core/Layout/LayoutKind.cs`.

## Visual rules
- Use `UnityEditor.UIElements.Toolbar` and friends.
- Icons via `EditorGUIUtility.IconContent("Refresh")`, `"d_FilterByType"`, etc. Place
  every icon name behind a private `static readonly` field for easy theming.
- Toggles default to: `Show Packages = false`, `Show Built-ins = false`,
  `MiniMap = true`.
- Search field min-width: 180px, expands to 320px when window is wide.

## Wiring in the window
In `AssemblyArchitectWindow.CreateGUI`, after the UXML is loaded:
```csharp
var toolbarHost = root.Q<VisualElement>("toolbar");
_toolbar = new AssemblyArchitectToolbar();
toolbarHost.Add(_toolbar);
_toolbar.RefreshRequested += () => /* TODO Task 3.4 */;
_toolbar.LayoutRequested  += kind => /* TODO Task 3.4 */;
// ...etc. Stubs only.
```

## Acceptance criteria
- All controls are visible and clickable.
- Each event fires (verify via `Debug.Log` in the stub, then remove the logs before
  the commit).
- Saved toggle states persist across domain reload via `[SerializeField]` on the window
  (forwarded to the toolbar through a `LoadState`/`SaveState` API).
- Console clean.

## Out of scope
- Actually performing refresh / layout / save (Phase 3+).
- Filter behavior (Task 5.2).
