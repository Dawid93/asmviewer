# Task 0.2 — Meta files & repo-level editor config

## Goal
Make sure the repository is friendly to deterministic CI runs and consistent code style.

## Steps
1. Open the Unity Editor once and let it regenerate `.meta` files for every file/folder
   added in Task 0.1. Commit the `.meta` files together with their assets.
2. At the repository root (next to `Assets/` and `Packages/`), create `.editorconfig`:
   ```ini
   root = true

   [*]
   charset = utf-8
   end_of_line = crlf
   insert_final_newline = true
   trim_trailing_whitespace = true

   [*.cs]
   indent_style = space
   indent_size = 4

   [*.{json,uxml,uss,asmdef,asmref,md,yml,yaml}]
   indent_style = space
   indent_size = 2
   ```
3. Add a `.gitattributes` (only if missing) at repo root with:
   ```
   * text=auto eol=lf
   *.cs    text eol=crlf
   *.meta  text eol=lf
   *.asset text eol=lf
   ```
4. Create `Packages/com.<vendor>.assembly-architect/Documentation~/index.md` containing
   a single placeholder line: `# Assembly Architect (docs WIP)`. The trailing `~` keeps
   this folder out of compilation.
5. Confirm `Tests/Editor/AssemblyArchitect.Tests.asmdef` is recognized by **Window ▸
   General ▸ Test Runner** under the **EditMode** tab (no tests yet, but the assembly
   should appear).

## Acceptance criteria
- No `.meta`-less files inside the package folder.
- `.editorconfig` and `.gitattributes` exist at the repo root.
- Test Runner lists `AssemblyArchitect.Tests` even though it contains no tests yet.
- Console is clean.

## Out of scope
- CI configuration files (later, in distribution phase).
