# Task 3.4 — Initial population & refresh pipeline

## Goal
Connect the data layer to the visual layer so the window actually shows the project's
asmdefs at startup, and stays in sync with on-disk changes.

## Files to edit
- `Editor/Window/AssemblyArchitectWindow.cs`
- `Editor/Graph/AsmDefGraphView.cs` (add helper if needed)
- `Editor/Core/Layout/LayoutKind.cs` (already exists)

## Specification

### Window state
Inside `AssemblyArchitectWindow`:
```csharp
private AsmDefRepository _repo;
private AsmDefGraphView _graphView;
private AssemblyArchitectToolbar _toolbar;
private DependencyGraphModel _model;
private LayoutKind _currentLayout = LayoutKind.Hierarchical;
private readonly Dictionary<string, Vector2> _positions = new();
```

### `OnEnable`
1. `_repo = new AsmDefRepository();`
2. `_repo.Changed += ScheduleRebuild;`
3. `EditorApplication.delayCall += Rebuild;` — initial paint after the UI is built.

### `OnDisable`
- Unsubscribe from `_repo.Changed`.

### `ScheduleRebuild`
- Coalesce multiple notifications using the same `Debouncer` helper from Task 3.3,
  with a 100 ms window. The end action is `Rebuild()`.

### `Rebuild`
1. Remember `_graphView.viewTransform.position` and scale. Remember selected node id.
2. `var data = _repo.LoadAll();`
3. `_model = DependencyGraphModel.Build(data);`
4. Compute layout:
   ```csharp
   var layout = _currentLayout == LayoutKind.Hierarchical
       ? (IGraphLayout)new HierarchicalLayout()
       : new ForceDirectedLayout();
   var fresh = layout.Compute(_model, new LayoutOptions());
   ```
5. Merge into `_positions`: only fill entries that are still missing — never overwrite
   user-moved nodes.
6. `_graphView.Populate(_model, _positions);`
7. Restore viewport and selection.
8. Update `status-label` to `"{nodes} asmdefs · {edges} references · {missing} missing · {cycles} cycles"`.
   (Cycle count uses `CycleDetector.FindCycles(_model).Count`.)

### Toolbar wiring
- `RefreshRequested` ⇒ `Rebuild()`.
- `LayoutRequested` ⇒ set `_currentLayout`, **clear `_positions`**, then `Rebuild()`.
- `ShowPackagesChanged` / `ShowBuiltInsChanged` ⇒ later (Task 5.2). For now, just store
  the bools on the window and call `Rebuild`.
- `MiniMapToggled` ⇒ Task 5.3.
- `SaveLayoutRequested` ⇒ Task 5.4.
- `SearchChanged` ⇒ Task 5.2.

### GraphView event wiring
- `_graphView.NodeSelected += OnNodeSelected;` (handler stub for now — inspector
  panel arrives in Task 4.4).
- `_graphView.EdgeAddRequested += OnEdgeAdd;` — stub, will dispatch
  `AddReferenceCommand` in Task 4.1.
- `_graphView.EdgeRemoveRequested += OnEdgeRemove;` — stub, Task 4.2.
- `_graphView.NodePositionChanged += (id, pos) => _positions[id] = pos;`

## Acceptance criteria
- Opening the window in a project with several asmdefs renders them all immediately
  with edges drawn.
- Creating a new asmdef in the Project window causes the graph to rebuild within ~100 ms.
- Moving a node and switching layouts via the toolbar **does not** discard the moved
  position for nodes that already had user positions; new nodes get fresh positions.
- Status bar reflects accurate counts after every rebuild.
- Console clean.

## Out of scope
- Persisting positions to disk (Task 5.4).
- Filter / search / mini-map (Task 5.x).
- Inspector panel (Task 4.4).
