# Task 1.6 — Layout engines (Hierarchical & Force-Directed)

## Goal
Compute 2-D positions for every node so the GraphView has a sensible default layout.

## Files to create
- `Editor/Core/Layout/IGraphLayout.cs`
- `Editor/Core/Layout/HierarchicalLayout.cs`
- `Editor/Core/Layout/ForceDirectedLayout.cs`
- `Editor/Core/Layout/LayoutOptions.cs`
- `Tests/Editor/LayoutTests.cs`

## Specification

### `IGraphLayout`
```csharp
internal interface IGraphLayout {
    IReadOnlyDictionary<string, Vector2> Compute(
        DependencyGraphModel graph, LayoutOptions options);
}
```
- `Vector2` is `UnityEngine.Vector2`.
- `LayoutOptions` carries: node size (default 220×80), horizontal spacing (default 80),
  vertical spacing (default 60), random seed (default `42`), iteration count where
  applicable.

### `HierarchicalLayout` (Sugiyama-style)
1. Reduce to a DAG by removing one edge per cycle (use `CycleDetector` results;
   pick the lexicographically smaller `(source,target)` to remove).
2. **Layering**: assign each node a layer = longest path from any source.
3. **Ordering** within a layer: barycenter heuristic, 4 sweeps top-down + bottom-up.
4. **Coordinates**: `x = column * (nodeWidth + hSpacing)`,
   `y = layer * (nodeHeight + vSpacing)`. Center each layer horizontally.

### `ForceDirectedLayout`
- Fruchterman–Reingold:
  - Initial positions: deterministic PRNG (`System.Random` seeded by
    `options.Seed`) inside a square of side `sqrt(nodeCount) * (nodeWidth + hSpacing)`.
  - Iterations: `options.Iterations` (default `200`).
  - Repulsive force between every pair of nodes; attractive force along edges; cooling
    schedule `t = t0 * (1 - i/iterations)`.

### Determinism
- Both layouts must produce **byte-identical** output across runs given the same input
  + same `LayoutOptions.Seed`. Tests will assert this.

## Tests
- `Compute` on the same input twice ⇒ exact dictionary equality.
- Hierarchical layout on a chain A→B→C places them on three distinct layers (different
  `y`).
- Force-directed layout on two disconnected pairs results in noticeably separated
  centroids (assert distance > nodeWidth).

## Acceptance criteria
- Both layouts produce a position for **every** node id.
- Tests pass.
- No Unity Editor APIs referenced; only `UnityEngine.Vector2` from the runtime module.

## Out of scope
- Persistence of node positions (Task 5.4).
- Applying positions to the GraphView (Task 3.4).
