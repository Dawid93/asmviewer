# Task 7.2 — Documentation

## Goal
Replace the placeholder `Documentation~/index.md` with proper user docs, and fill
the package's `README.md`.

## Files to create / edit

- `Documentation~/installation.md`
- `Documentation~/quick-start.md`
- `Documentation~/window-overview.md`

- `Documentation~/faq.md`
- `Documentation~/images/` (place all screenshots here)
- `README.md` at the package root

## Specification

### `README.md` (package root)
Sections in order:
1. **Title + tagline** ("Assembly Architect — visualize, edit, and validate Unity
   assembly definitions in a graph view.").
2. **Screenshot** (single hero image).
3. **Features** bullet list.
4. **Requirements** ("Unity 6000.0 or newer, Editor only").
5. **Installation** — Package Manager via Git URL **and** local tarball, with
   copy-pasteable snippets.
6. **Quick start** (~5 numbered steps).
7. **Documentation** link to `Documentation~/index.md`.
8. **Samples** description.
9. **Contributing** — pointer to issue tracker.
10. **License** — MIT.

### `Documentation~/index.md`
Acts as a table of contents linking to every other markdown file under
`Documentation~/`.

### `quick-start.md`
- "Open the window via **Window ▸ Analysis ▸ Assembly Architect**."
- "Drag from one node's right port to another's left port to add a reference."
- "Select a node to edit its asmdef in the right panel."
- "When a cycle is detected, follow the orange banner to focus on it."
- Each step paired with a screenshot.

### `window-overview.md`
- Annotated screenshot identifying: toolbar, cycle banner, graph host, mini-map,
  inspector, status bar.

### `inspector-reference.md`
- Field-by-field explanation matching Unity's official asmdef docs but specific to
  this UI.

### `cycle-handling.md`
- What counts as a cycle, why they are problematic, how to use the focus button,
  how to optionally fail builds (Task 7.3).

### `project-settings.md`
- Walkthrough of every option in the Project Settings page.

### `faq.md`
- "Why doesn't editing a registry package work?" (read-only by design).
- "Where are node positions stored?" (LayoutCache file path, team-shared toggle).
- "How do I uninstall the package?".

### Style guide
- Use H2/H3 only; no H1 inside files (the file title comes from the first heading).
- Image paths relative: `images/window-overview.png`.
- Wrap lines at ~100 chars.

## Acceptance criteria
- Every link in `Documentation~/index.md` resolves.
- README renders correctly on package-manager preview (line breaks, code blocks).
- All screenshots are present (placeholders are acceptable but must show actual UI).
- `LICENSE.md` content matches the license referenced by the README.

## Out of scope
- Translating documentation.
- Video tutorials.
