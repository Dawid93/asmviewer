# Task 1.5 — Implement `CycleDetector`

## Goal
Detect every dependency cycle in a `DependencyGraphModel`. Used by:
- the visual cycle highlight (Task 5.1),
- the `AddReferenceCommand` validator (Task 4.1),
- the optional build-failing pre-process (Task 7.3).

## Files to create
- `Editor/Core/CycleDetector.cs`
- `Tests/Editor/CycleDetectorTests.cs`

## Specification

### API
```csharp
internal static class CycleDetector {
    public static IReadOnlyList<IReadOnlyList<string>> FindCycles(DependencyGraphModel graph);
    public static bool WouldCreateCycle(
        DependencyGraphModel graph, string sourceId, string targetId);
}
```

### `FindCycles`
- Implement Tarjan's strongly-connected-components algorithm.
- Return every SCC of size ≥ 2.
- Additionally include any node that has a self-edge as a single-element cycle.
- Each returned list is sorted ascending by node id; the outer list is sorted by the
  first element of each inner list.

### `WouldCreateCycle`
- Reachability check from `targetId` back to `sourceId` in the existing graph.
- O(V + E), no allocations on the hot path beyond a `Stack<string>` and a
  `HashSet<string>`.

## Tests (must all pass)
1. **Empty graph** ⇒ no cycles.
2. **Pure DAG** A→B→C ⇒ no cycles, `WouldCreateCycle(C, A)` returns true,
   `WouldCreateCycle(A, C)` returns false.
3. **Two-cycle** A→B, B→A ⇒ one SCC `{A, B}`.
4. **Self-loop** A→A ⇒ one cycle `{A}`.
5. **Nested SCCs**: A→B→C→A and D→E→D, plus C→D ⇒ two cycles, no merging.
6. **Disconnected components** still detected independently.
